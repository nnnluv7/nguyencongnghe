# Pikachu NCN — Onet matching game

Public route: `/pikachu/`. A free, single-player browser game sharing the NCN navigation, theme, announcements and account controls. Scores and unfinished runs are browser-local; this game does not submit to the snake multiplayer leaderboard. Facebook remains a separate, unfinished integration.

## Rules and interaction

- Match identical non-empty tiles along orthogonal paths with at most two turns. One empty cell around the grid permits classic outside-frame paths.
- 80 tiles and 20 locally drawn SVG portraits. Desktop classic boards are 10 × 8; phone boards are 8 × 10. Daily boards always use 8 × 10 and the same seeded arrangement for the Vietnam date.
- Classic and Relax have 30 named stages and 12 movement rules. The first five keep the original fixed/down/left/up/right sequence; later stages include inward/outward rows and columns, alternating rows/columns, and a direction that cycles after each pair. Classic gives six minutes per stage; Relax has no deadline. Daily is one six-minute board.
- Every pair earns 100 points. Consecutive pairs within five active seconds build a multiplier, capped at five. Timed stages grant five bonus points per remaining second when cleared.
- Each stage has three hints and three shuffles. Manual shuffle costs 15 seconds in timed modes. A board with no legal pair automatically reshuffles for free, preserving every tile and its empty slots.
- Pause, help, shared account/navigation/search and leaving the tab freeze the timer. Returning requires an explicit resume. Saved runs resume from their stored board, score, stage, time and assist counts; the combo resets on reload. Clearing a non-final stage saves the next board as a checkpoint, including its stage number and accumulated score. Version-one saves from the original five-stage release remain valid. Storage denial or malformed data cannot prevent play.
- Sound starts muted and is synthesized only after opt-in. Reduced motion follows the device preference and can be changed in Help. All portrait/cover/hero SVGs are local; there are no sprite-service dependencies.
- Keyboard: arrows move within the board, Enter/Space select, Esc clears selection, H hints, P pauses/resumes. Fullscreen uses a compact, fixed layout with the board fitted to both available width and height, compact score/time/assist controls, safe-area padding, and no page scrolling. Rotation preserves the board. A window-filling fallback is available when native fullscreen is absent or rejected. Help/confirmation dialogs remain inside the fullscreen root.

## Site integration

The canonical tool config, static initial configs/menus, homepage card order, catalogue seed, library, search, sitemap, public-page allowlist and redirects include Pikachu. `sync-site-config.mjs` now orders static homepage cards exactly as hydration does, preventing a new, taller game card from changing grid height during page load. The shared account controller now catches a blocked localStorage getter before reading its legacy display hint; Identity authorization is unchanged.

## Validation

- Node tests compare pathfinding with an independent breadth-first search for all 4,608 combinations of 3 × 3 obstacle masks and endpoint pairs; check reproducible boards, pair-count preservation, every gravity direction, complete playthroughs, reshuffle recovery, save validation and Vietnam midnight.
- Browser fixtures exercise real clicks and phone taps, stage progression and stage 30, hints, shuffle costs, timer expiry, Relax, deterministic daily boards, pause/restore, shared UI, blocked storage, 320–1440 px layouts and portal discovery. Fixtures never create production accounts or write production game scores.
- Shared-account browser checks and the full shared-page layout suite are run after integration. Netlify archives are packaged using the production bundler.

## Fullscreen and screen-awake follow-up

The previous fullscreen rule only constrained the outer height and allowed overflow, retaining the long portrait page and a 500px welcome minimum. The replacement is a two-row application layout with a bounded play area and compact HUD; a ResizeObserver sizes the grid without reshuffling it. Native fullscreen requests hide navigation UI where the browser supports it.

Screen Wake Lock is requested only while fullscreen/the fitted game view is active and the document is visible. Exit, app switching, and pagehide release it; returning to a still-active fullscreen view reacquires it. Late grants after exit are immediately released. Denial, unsupported APIs, and platform revocation update an unobtrusive status without stopping the game or retrying in a loop. The system can refuse or revoke wake locks, so physical-device sleep prevention depends on its permission and power policy.

Additional checks:

```sh
node --test tests/ncn-pikachu*.test.mjs
node tests/browser/ncn-pikachu-screen.mjs
```

These include real browser native fullscreen, a fitted fallback, portrait and short landscape viewports, rotation, exit/focus cleanup, matching overlays, continued-stage checkpoints, and injected WakeLock grant/denial/race scenarios. Physical Android sleep is not simulated by a desktop browser.
