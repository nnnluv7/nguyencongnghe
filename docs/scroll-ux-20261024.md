# Print scrolling, shared chrome and compact cash form

The print editor previously placed a scrolling control rail next to a scrolling paper preview inside a scrolling page. This made it difficult to find the active field and return to Print.

- Print remains a single original button in a sticky workspace bar.
- Desktop forms use the document scroll; the paper stays visible beside them.
- Mobile switches between paper and input panels without recreating inputs.
- Format/import settings and help start collapsed; content fields start expanded.
- The active print field is identified and highlighted on screen. Focusing a desktop form field reveals its position on the paper.
- The announcement, toolbar and floating menu button hide on a downward gesture and return on a shorter upward gesture. Small direction reversals do not flicker. Keyboard navigation, menus, account controls and page restoration reveal the chrome.
- Reduced-motion preferences disable movement transitions.
- The approved simple cash layout remains intact in a centered Liquid Glass card up to 480 px wide; the denomination table is at most 400 px wide. Nine denominations and comma-formatted ERP remain unchanged.

The existing print renderers, source artwork, fonts, protected role templates and API authorization are unchanged. Shared assets use the existing max-age=0/must-revalidate policy in public/_headers; updated module imports have a new version URL.

Verification:
- Existing Node suite plus scroll-direction behavioral cases run in NCN checks.
- The NCN UI browser workflow exercises desktop/mobile editing, stored field values after panel switches, active-field highlighting, visible print actions, scroll direction, keyboard recovery, legacy workspaces, FIFO, cash widths, ERP commas, menu access and reduced motion.
- Browser screenshots and results are kept as the ncn-scroll-ui Actions artifact. Announcement data is synthetic only in the local test server.
- The interactive editing environment was disconnected for this change. Verification is performed in GitHub's Chromium workflow rather than an authenticated production browser session. No account or price data is used.
